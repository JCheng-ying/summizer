# Muse Code Wants Your Data: Meta's Muse Spark 1.2 and Muse Code approach the intelligence frontier at a discount
https://www.deeplearning.ai/the-batch/muse-code-wants-your-data/

这篇文章讨论的是训练数据竞争进入了一个新阶段:当高质量代码数据变得稀缺,Meta 想出的办法不是继续爬公开仓库,而是直接用"更便宜的 API 价格"去换开发者交出自己敲代码的完整过程。

文章指出,Meta 发布了命令行编程智能体 Muse Code,以及驱动它的低成本模型 Muse Spark 1.2。技术设计上有几个细节值得展开:主智能体会把任务分给一组"常驻"子智能体,这些子智能体在整个会话期间不会被销毁重建,各自在独立的工作副本(worktree)里并行改代码,还能自己保留已经学过的仓库上下文、自主判断什么时候该向主智能体汇报;整个过程(每次模型调用、工具执行、计划确认、文件修改)都写日志到本地,一旦崩溃可以从上次进度继续,不用推倒重来。性能上,Muse Spark 1.2 在 Artificial Analysis 智能指数上拿到 57 分,排第六(高于 Grok 4.5,低于 Qwen3.8-Max),比自己上个月的 1.1 版本提升了 4 分;在 Vals AI 的"金融分析师智能体"评测里排名第一,而且比第二名 Claude Opus 5 便宜了将近十倍、耗时也只要一半。

文章真正的重点在定价策略上。Meta 给 Muse Spark 1.2 定了两档价格:标准档每百万输入/缓存/输出 token 收 1.25/0.15/4.25 美元,提示词和输出不会被用来训练;贡献者档只收 0.10/0.002/0.20 美元(便宜了十几倍),条件是你的提示词和输出会被 Meta 拿去训练模型,而且这个便宜档位有速率限制(每团队每分钟 100 次请求,标准档是 3000 次),等于是专门瞄准了个人开发者和小团队——文章点出这恰恰是"最不太可能请得起律师、也最可能把整个产品逻辑都写在被智能体读取的仓库里"的那批人。

个人看法:这篇文章和前几天 Hugging Face 发布 The Stack v3 那篇是同一个瓶颈问题的两种不同解法。The Stack v3 解决的是"过去已经写好的公开代码"不够新、不够全的问题,靠重新爬取 GitHub 补两年的量;但原文这次明确指出了 The Stack 这类静态代码仓库爬取方案的一个结构性局限——公开仓库只能看到"打磨好的最终代码",看不到写代码过程中的推理、试错和修复,而这恰恰是训练"编程智能体"(不是"代码补全模型")最需要的数据。Meta 的 Muse Code 定价策略,本质上是想直接买下这种"过程数据"——不是靠爬,是靠开发者自己主动用这个折扣价交换。这两篇放在一起看,说明训练数据竞争正在从"谁能爬到更多代码"升级到"谁能拿到更完整的编程决策过程记录",这是一个新的、之前没被单独讨论过的数据获取维度。

个人看法:文章末尾提到的价格战背景值得单独记一笔——这次 Meta 的折扣价发布,正好卡在 OpenAI 把 GPT-5.6 Luna 价格砍 80%、DeepSeek-V4-Flash-0731 用 0.14/0.28 美元每百万 token 定价这两件事之后不久,Meta 的贡献者档价格比这两家都低。这进一步印证了之前 DeepSeek 那篇文章里提到的判断:**AI 板块**里"轻量高性价比模型"这条赛道的价格竞争烈度还在持续升级,而且现在多了一个新变量——不只是比谁模型更聪明、更便宜,还要比谁能用价格换到最稀缺的训练数据。这对纯靠 API 调用量赚钱的模型厂商是一个警示信号:如果"用数据换低价"成为行业标配打法,单纯的 API 定价战会进一步压缩利润空间,真正的竞争会转移到"谁能把数据变现成更强的下一代模型"这个更长的周期上。风险与不确定性在于,这类"贡献者档"能不能真的换来足够高质量、足够大规模的数据,原文并没有给出验证,值得后续跟踪 Meta 下一版 Muse 模型有没有实质性的编程能力提升作为验证信号。
