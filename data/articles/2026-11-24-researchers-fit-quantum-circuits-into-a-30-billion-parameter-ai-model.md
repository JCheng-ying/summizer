# Researchers Fit Quantum Circuits Into a 30 Billion-Parameter AI Model
https://thequantuminsider.com/2026/11/24/researchers-fit-quantum-circuits-into-a-30-billion-parameter-ai-model/

这篇文章讨论的是"量子 + 大模型"这个被反复炒作的方向里,一次相对诚实的实验:量子处理器能不能接手生产级大语言模型里的一小部分计算。结论其实是负面的——能接手,但比经典方法既不更准、也慢得多。正因为它把短板写得很清楚,反而比很多宣传更有参考价值。

文章指出,来自 Multiverse Computing 和多伦多大学的研究团队,拿阿里云开发的 Qwen3(305 亿参数)做实验,把模型中间连续 8 个 block(接近 50 亿参数)拿掉,换成一个只有 145,281 个可训练参数、可在量子处理器上运行的模块,参数量减少约 16%。在模拟中,改造后的模型在 WikiText-2 上的困惑度只差 0.9%,在 C4 上看不出明显差别。技术上的处理方式是:每个 token 在这一层用 2048 个数表示,一次性装进一个量子电路需要太多量子比特或太长的门序列,所以团队把 2048 个数拆成 32 组、每组 64 个,分别交给 32 个独立的 8 量子比特电路,每个电路分四个阶段读入数据,前后用经典计算做信息混合和重组。训练分两步,先让模块复现被替换 block 的输出(类似蒸馏),再放回模型里针对下一个 token 预测微调,两步都在经典计算机上精确模拟完成。

但文章同时列出了几个关键限制。第一是速度:在 156 量子比特的 IBM Heron 处理器上,一次只能并行跑 14 个电路,处理一个 token 需要三批,每个 token 占用约 90 秒处理器时间;完整跑一遍 WikiText-2 评测大约需要百万次电路提交。第二是精度:参数量相近的普通神经网络,在几乎所有对比中都比量子模块预测得更好;在单层测试里,关掉纠缠或固定电路参数反而得分更高,研究者自己也承认还不能确定"训练过的纠缠电路"对这个任务有没有好处。第三是真机噪声比模拟估计的更大,真机只跑了 15 个 token 的短生成。第四,研究没有和主流的经典压缩方法(剪层 + 低精度量化)对比。还有一个结构性问题:量子模块对每个 token 独立处理,不负责 token 之间的交互,也就是说 Transformer 最核心的 attention 部分并没有被替换。

个人看法:这篇我会把它当成量子计算板块的"降温信号"而不是利好。它其实证明了一个更朴素的事实:大模型中间那几层本来就有大量冗余,砍掉 8 层再用一个小模块补回来,经典网络就能做到,而且做得更好——这和 Multiverse 自己主打的张量网络模型压缩业务逻辑是一致的,量子电路在这里更像是一种"也可以用"的替代实现。和之前写的 [Q.ANT 光子 + GPU 混合系统跑语言模型](2026-11-17-q-ant-demonstrates-hybrid-photonic-gpu-system-for-language-models.md) 类似,这类"新型计算硬件接管大模型一部分"的实验,现阶段真正卡住的瓶颈不是能不能跑通,而是吞吐量——每 token 90 秒和 GPU 的毫秒级之间差了五个数量级以上。

目前来看量子和 AI 结合大概有三条路:1. 量子算法加速 AI 本身(本文这条,离实用最远);2. AI 帮量子,例如用机器学习做纠错解码、校准和电路编译,这条已经在落地;3. 量子和 GPU 在 HPC 里分工,各自算擅长的部分。投资上我会更看重第二、三条:受益层次第一层仍然是 GPU 和混合编排软件(NVIDIA CUDA-Q 这类把 QPU 当协处理器接入的平台),因为无论量子模块多小,训练和模拟都还在 GPU 上完成;第二层是 IBM 这类提供云端量子硬件访问的厂商,它们从研究机构的实验时长里获得收入。所以这篇对 AI 板块几乎没有影响,对量子计算板块是中性偏谨慎。值得跟踪的是研究者提出的下一步——保留 attention、只压缩其余部分,并与经典压缩方法正面对比;如果那时量子模块在同等参数下还落后,这条路线短期内就很难有商业意义。
