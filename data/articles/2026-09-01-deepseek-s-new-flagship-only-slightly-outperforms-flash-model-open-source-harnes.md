# DeepSeek's New Flagship Only Slightly Outperforms Flash Model; Open Source Harness Draws Interest
https://www.deeplearning.ai/the-batch/deepseek-v4-pro-gets-refreshed/

先说明一个信源上的问题:这篇文章的标题是关于 DeepSeek 新旗舰模型的,但抓取到的正文全文从头到尾没有提到 DeepSeek,内容实际讲的是另一件事——模型竞争正在从"跑分"和"成本"之外,卷出第三个维度:速度。这大概率是原网站的标题和正文出现了错配(可能是编辑发布时挂错了标题),这里按正文实际内容如实梳理,不去编造标题暗示的 DeepSeek 相关内容。

文章指出,OpenAI 和 Cerebras 预览了 Ultrafast,一个让 GPT-5.6 Sol 跑在 Cerebras 硬件(而不是 OpenAI 自家基础设施)上的新 API 服务档位。具体数字上,Ultrafast 号称每秒最高 750 个输出 token,而 Artificial Analysis 测得 GPT-5.6 Sol 在 OpenAI 自家 API 上(max 推理档)只有每秒 65 个 token,意味着 Ultrafast 快了大约 11 倍;在六个质量对齐的 GDPVal 任务(OpenAI 用来衡量真实经济价值工作任务的基准)上,Cerebras 测得 Ultrafast 平均每个任务 83 秒,标准版 Sol 需要 7.7 分钟,端到端提速 5.6 倍。文章解释了这里的技术原理:Cerebras 的硬件把 GPT-5.6 Sol 的权重直接放进 44GB 的片上 SRAM 里,避免了 GPU 推理里那种频繁访问外部内存造成的瓶颈。一个更直观的例子是,Ultrafast 用 11 小时 11 分钟就答完了 Humanity's Last Exam(涵盖 100 多个学科的专家级问题测试)全部 2500 道题,而 Claude Fable 5 需要 78 小时 27 分钟,快了约 7 倍。

文章还指出,同一周里还有另外两款模型也是以"速度"作为核心卖点发布的:Google 发布了 Gemini 3.7 Flash(Artificial Analysis 测得每秒 330 个输出 token,首 token 等待 13.2 秒,智能指数从上一代的 52 分提升到 56 分),Nvidia 发布了 Nemotron 3.5 Lightning(Nvidia 官方称比同类模型输出快 4 倍、agentic 任务完成快 30%,Artificial Analysis 测得平均每秒 302 个输出 token、首 token 等待 7.5 秒;配套发布的开源路由库 NeMo Switchyard 能把一个 agentic 工作流的每一步分配给最适合该步骤速度/质量/成本需求的模型,Nvidia 表示比全程用单一大模型跑完整个流程,成本能降到 Claude Opus 4.8 单独运行成本的约三分之一)。文章特别解释了"速度"这个词在 AI 里实际包含两个不同的度量:延迟(首 token 等待时间)和吞吐量(启动后每秒能产生多少 token),不同模型和硬件在这两个维度上的表现可能完全不同。文章还提到 OpenAI 这周同时公布了 Jalapeño(和 Broadcom 合作研发的新推理芯片)的首批测试结果,在跑 OpenAI 自家模型和开源权重模型时都显示出不错的延迟和吞吐量表现,不过芯片厂商还需要在速度、支持的用户总数、硬件功耗之间做平衡,这些因素共同决定推理的成本和可靠性。

文章的落脚点是,这类速度提升改变的不只是"模型能不能做好一个固定任务",而是"这类速度能让哪些原本不可行的应用变得可行"——语音助手这类实时对话场景里,用户能直接感知到延迟(人类对话的轮次间隔通常在 0.3 到 1 秒左右,超过这个范围就会感觉"卡");用 agent 写代码时,等待几分钟的结果足够让人分心、忘记原本的思路,重新捡起问题需要额外的认知负担;低延迟高吞吐对"持续监控系统/网站/安全画面并实时响应"这类常驻 agent 尤其关键,因为分析耗时哪怕只有一分钟也可能错过行动窗口;搜索、代码执行、数据检索这些工具调用同样高度依赖延迟和吞吐表现。

个人看法:抛开标题的错配问题,这篇文章实际内容值得记录的判断是——**AI 板块**里的竞争维度正在从"跑分/成本"这两维,扩展成"跑分/成本/速度"三维,而且速度这一维正在从纯粹的用户体验优化,变成决定"哪些应用能不能做"的硬约束——这和之前读过的[Grok 4.6](2026-08-22-grok-4-6-rivals-claude-opus-5-and-gpt-5-6-sol-at-a-lower-price.md)那篇里"完成任务需要几步"这个维度是同一个大趋势的延伸,模型厂商正在把"用更少的时间/步骤完成同样的任务"当作和跑分同等重要的竞争指标来公开宣传。用"先找瓶颈"的方法看,这里真正的瓶颈是推理硬件架构——Cerebras 靠的是把权重整个放进片上 SRAM 避免访存瓶颈,这是一条和标准 GPU 推理完全不同的硬件路线,值得作为"推理侧硬件多元化"的一个具体案例持续跟踪,尤其是考虑到 OpenAI 同时还在和 Broadcom 合作自研推理芯片 Jalapeño——头部模型厂商正在同时押注多条推理硬件路线(自研芯片+Cerebras 这类专用硬件伙伴),这对 Nvidia 在推理侧的护城河是一个值得关注的分散化信号,尽管 Nvidia 自己的 Nemotron 3.5 Lightning 和 NeMo Switchyard 路由方案也在这场速度竞赛里占有一席之地。受益层次上,第一层是能提供极致推理速度的专用硬件公司(Cerebras、以及自研芯片的 OpenAI/Broadcom 组合);第二层是像 NeMo Switchyard 这类"智能路由"软件,如果"用小模型处理简单步骤、大模型处理复杂步骤"这类混合调度思路被证明能大幅降低成本,会是一个独立于底层硬件之外的软件层机会。
