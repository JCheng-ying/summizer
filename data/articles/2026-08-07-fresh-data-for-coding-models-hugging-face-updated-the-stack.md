# Fresh Data for Coding Models: Hugging Face updated The Stack, the largest crawl of public GitHub repositories
https://www.deeplearning.ai/the-batch/fresh-data-for-coding-models-hugging-face-updated-the-stack-the-largest-crawl-of-public-github-repositories/

这篇文章讨论的是一个容易被忽略、但支撑着整个"AI 写代码"叙事的底层环节:训练代码模型用的开源数据集,本身也需要持续更新维护,而且这件事一度被搁置了很久。

文章指出,Hugging Face 发布了 The Stack v3,是目前最大、最新的开源代码数据集快照,由 Anton Lozhkov 团队完成。和上一版 v2(2024 年发布,来自 Software Heritage 存档,只提供文件标识符、要用户自己再去别处抓取实际文件)不同,v3 是直接爬 GitHub,并且给的是完整的仓库加文件本身,而不只是索引——这个区别很关键,因为文章解释,今天的编程助手越来越需要理解"一个函数依赖另一个文件里的哪个定义"这种跨文件的项目级上下文,而不是只补全孤立的代码片段,这就要求训练数据本身是按开发者组织代码的方式打包的,而不是零散的文件集合。数据规模上,v3 提供两个版本:训练用的精筛版 15.9TB(约 4.9 万亿 token,713 种语言,173 万个仓库,经过去重、质量过滤和个人信息清洗),以及未筛选的完整版 113.7TB(224 万个仓库,给想自己定制过滤规则的团队用)。知识截止到 2025 年 8 月 7 日,比 v2 又往后推了大约两年。

文章也提到了几个技术细节和局限:授权判断依赖自动化工具和仓库元数据,存在误判风险;数据里可能仍然残留开发者不小心公开提交的邮箱、密钥等敏感信息;数据可能包含恶意代码;此前 v2 因为一个 bug 意外丢弃了比预期更多的文件,这次 v3 的流程修正了这个问题。文章还提到一个背景信息:The Stack 历代版本都是 Hugging Face 和 ServiceNow 主导的 BigCode 项目做的,早期版本训出了 StarCoderBase 和 StarCoder2,英伟达、JetBrains 等公司也用过之前版本的数据训练模型。

个人看法:文章原文提出了一个值得展开的观察——2025 年的 GitHub 快照里,必然包含了大量由 AI 编程助手自己写出来或辅助写出来的代码,这意味着下一代代码模型,有一部分是在"上一代模型的输出"上训练出来的。这是一个值得持续关注的结构性问题:如果这种"AI 训 AI"的数据循环持续下去,长期看数据质量会不会因为模型输出的同质化而逐渐退化(类似"模型崩溃"的担忧在文本领域已经被讨论过,代码领域大概率也会遇到同样的问题),还是说因为代码有可验证对错的特性(能跑、能测试),这种循环反而是良性的——这一点原文没有给出答案,但提示了一个可以拿实际数据验证的研究方向:对比 AI 编程助手普及前后提交的代码,看训练效果有没有系统性差异。

个人看法:这类基础设施层的数据更新,单独看不构成一个可交易的事件,但**AI 板块**里"代码模型"这个细分赛道(GitHub Copilot、Claude Code、各家编程助手)的竞争力,某种程度上取决于谁能拿到更新、更干净、更贴近开发者实际工作流的训练数据——这次更新本质上是把这个瓶颈往后推了两年,值得作为整个开源代码模型生态(StarCoder 系、以及任何依赖开源代码数据训练的编程模型)的一个基础设施利好信号记一笔,而不必单独归到某家具体公司头上。
