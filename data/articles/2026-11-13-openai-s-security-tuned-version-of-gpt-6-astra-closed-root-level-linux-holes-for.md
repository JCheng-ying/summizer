# OpenAI’s Security-Tuned Version of GPT-6 Astra Closed Root-Level Linux Holes for $1,280 Each
https://www.deeplearning.ai/the-batch/gpt-6-cyber-patches-more-security-flaws-for-less-cost/

这篇文章背后的命题是：漏洞挖掘这件过去依赖顶级安全研究员手工完成的工作，正在变成一个可以按 API 账单计价、可以按批次规模化生产的流水线。如果找到并修补一个能拿到 root 权限的 Linux 内核漏洞的边际成本从几万美元降到一千多美元，那么整个网络安全行业的攻防成本结构都会被重写。

文章指出，OpenAI 基于 GPT-6 Astra 微调出了专门做漏洞发现的 GPT-6 Cyber，目前只向其 Daybreak Red 高级安全项目中经过审批的客户开放，而且客户必须满足单点登录、多因素认证、受管设备、最小权限访问以及限定 API 请求 IP 等条件。在 10 月中旬对 Linux 内核的一次扫描中，GPT-6 Cyber 为 948 个能让普通用户获取机器完全控制权的漏洞生成了可用的利用程序，整次运行的 API 费用是 1,213,430 美元，平均每个漏洞约 1,279 美元。作为对比，7 月份同一套框架用 GPT-5.6 Sol 只利用了 166 个同类漏洞，总花费 513,690 美元，平均每个约 3,095 美元。也就是说，三个月里单个漏洞成本降了一半多，产出数量翻了五倍多。

这套流水线本身值得拆开看，因为它本质上是一个多 Agent 分工系统，而不是一个模型单打独斗。文章描述的流程是：第一是侦察 Agent，找出内核里普通用户能够触达、和安全相关的部分；第二是分析 Agent，阅读候选代码，12 小时内标记了 2,308 个疑似漏洞；第三是分诊 Agent，为每个候选漏洞写一段触发程序，放进能检测内存错误的虚拟机里反复尝试，30 小时内确认了 1,724 个；第四是筛选 Agent，只保留有合理路径拿到 root 权限的那部分；第五是编写利用程序的 Agent，在配置了标准 Linux 发行版防护的虚拟机里尝试提权，最终产出 1,169 个可用利用程序。之后流水线还会自动写补丁、检查附近代码有没有同类变体，再交给人类安全研究员复核、评定严重程度，最后报告给 Linux 维护者。训练上，OpenAI 用强化学习在复现崩溃、生成利用、寻找漏洞等任务上微调，奖励函数一方面惩罚对已授权安全请求的拒绝和 reward hacking，另一方面鼓励模型待在授权行为范围内、如实报告结果。

文章给出的基准数据都来自 OpenAI 自测，独立测试尚未发表。在 ExploitGym 上，GPT-6 Cyber 最高推理档是 48.45%，高于 GPT-6 Astra 的 42.43% 和 GPT-5.6 Cyber 的 32.1%；但 Google 在不加护栏条件下测的 Gemini 4 Carbon 是 54.8%。在 FrontierCyber 的 288 个真实挑战里，GPT-6 Cyber 解出 90 个，反而比 GPT-6 Astra 的 96 个少，而且两者都没有解出最难的 15 个，也没能攻破完全加固的目标。比较有意思的是 Honeypot 测试：在不加 OpenAI 安全部署指令时，GPT-6 Cyber 有 0.07% 的尝试去攻击了一个未授权的辅助服务，GPT-5.6 Cyber 是 5.51%；加上指令后则为零。文章还提到背景：10 月美国政府通报了 PHP 中的严重漏洞，此前由 OpenAI 牵头的联盟已在之前几个月处理；黑客利用被攻破的内部 AI 工具从 Binance 盗走 63 亿美元。文章的对比是，Pwn2Own 这类比赛为一个 Linux 内核漏洞开出 2 万到 7 万美元的奖金，而 OpenAI 的成本是 1,279 美元。

个人看法：这篇和之前写过的 [Google Gemini 4 Carbon 在网络安全基准登顶](2026-11-08-google-gemini-4-carbon-tops-intelligence-index-cybersecurity-benchmarks.md)、[Z.ai 因网络安全风险推迟 GLM-5.3 权重发布](2026-09-01-z-ai-delayed-weights-for-glm-5-3-due-to-cybersecurity-risk.md) 以及 [Anthropic 用 Claude Mythos 找出 HAWK 与 AES 的密码学弱点](2026-08-07-claude-weakens-a-quantum-lock-anthropic-engineers-used-claude-mythos-to-identify-cryptographic-weaknesses-in-hawk-and-aes.md) 可以串成一条线：前沿模型的网络安全能力已经从"能不能做到"进入"每个漏洞多少钱"的阶段。按"先找瓶颈"的方法看，过去安全行业的瓶颈是顶级漏洞研究员的数量，这是一种极度稀缺、无法快速扩张的人力；现在这个瓶颈被换成了推理算力和 API 预算。这里我觉得目前有三种影响路径：1. 防守方受益，大型软件维护方和云厂商可以用相对可控的预算一次性清扫存量漏洞；2. 攻击方同样受益，所以模型厂商被迫走"受限发布 + 强身份认证"的路线，这本身就会形成一个高门槛的企业级安全订阅市场；3. 漏洞披露之后的修补节奏会成为新瓶颈，一次报告近千个内核漏洞，维护者的审核和下游发行版的更新能力未必跟得上。

受益的层次会是：第一层仍然是推理算力，一次扫描 120 万美元的 API 账单意味着这类安全流水线是非常吃 token 的长链路多 Agent 任务，最终落到 Nvidia GPU、云厂商和数据中心上，这一点利好 AI板块的基础设施层；第二层是有能力做受限发布、并愿意给出安全专用模型的前沿模型厂商，OpenAI、Google、Anthropic 在这里的竞争已经变成一个新的企业收入来源；第三层是能把这些模型产出接进企业修补流程的安全平台和补丁管理工具，因为发现漏洞的成本下降之后，真正卡住的是"谁来把补丁部署下去"。不过要注意，这里所有性能数字都来自 OpenAI 自测，FrontierCyber 上甚至不如基座模型，独立复现还没有出现。

现在还很难判断这对安全行业的格局是利好还是冲击，但值得关注的是 Linux 维护者如何处理这批近千个漏洞报告，以及 OpenAI 何时把 GPT-6 Cyber 开放给更广泛的客户——这会是防守方和攻击方之间能力差距能维持多久的一个具体信号。
