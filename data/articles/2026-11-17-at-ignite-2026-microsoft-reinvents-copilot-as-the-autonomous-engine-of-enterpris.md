# At Ignite 2026, Microsoft reinvents Copilot as the autonomous engine of enterprise work
https://siliconangle.com/2026/11/18/at-ignite-2026-microsoft-reinvents-copilot-as-the-autonomous-engine-of-enterprise-work/

先说明来源性质:这篇文章的内容基本来自 Microsoft 首席营销官 Jared Spataro 的官方博客,属于公司自己的发布会叙事,文中的功能描述都是厂商说法,实际效果未经独立验证。

这篇文章背后的命题是:企业 AI 正在从"员工问、助手答"的被动模式,转向"agent 自己盯着收件箱和项目流程、主动干活"的常驻模式。如果这个转变成立,企业软件的计价单位会慢慢从"每个员工一个席位"变成"每个 agent 完成了多少工作",而谁握有企业数据和身份权限,谁就握有这些 agent 的入口。

文章指出,Microsoft 在旧金山的 Ignite 2026 上把 Copilot 重新定位为"工作场所的操作系统",核心是一个叫 WorkIQ 的智能层。Spataro 给出的背景数字是,Microsoft 365 里存着大约 19.5 EB 的客户业务数据,每天还新增数十亿份文件、邮件和消息,单纯把 agent 接到这些数据上是不够的,WorkIQ 充当所有 Copilot agent 的集中推理层,负责检索数据、理解意图、筛出与任务相关的部分。在这之上,文章把这次更新拆成了几块。第一是入口,新的 Copilot 界面"Home"把聊天和一个叫 Cowork 的委派门户合在一起,其中的 Auto 会把用户请求路由到合适的模型和投入程度,复杂任务会建议从 Chat 转到 Cowork;Today 则扫描邮件、日历和 Teams 线程,列出当天要做的事并帮忙起草回复,目前在私有预览。第二是执行,Office 的完整能力被直接放进 Copilot 应用,文档在 Copilot 里生成并可以和同事共同编辑;Copilot Workspaces 是人和 agent 共用的画布,agent 写一段、通知人来审,人留评论再交给 agent 改。第三是最关键的 Autopilot,它面向参加 Frontier 抢先体验计划的用户开放,是一个常驻、全自主的 agent,有自己的 Microsoft Entra 身份、记忆和工具,会持续监听 Teams 频道和收件箱,能自动处理重复流程、跑完多步骤的供应商审查这类项目;IT 团队可以控制它的访问范围、随时叫停,它的登录和操作都记在自己名下,关键动作前会先征求用户同意。第四是应用和数据,几周后推出的 Copilot Code 让普通员工用自然语言生成仪表盘、桌面小组件和轻量业务应用,这些应用统一托管在受 IT 监控的 Copilot Managed Runtime 里;Agent 365 新增 Business Analytics,用类似 FinOps 的方式衡量每个 agent 完成的工作量和耗时来算投资回报,而不只是统计 token 消耗;Dynamics 365 进入 Copilot 后带来 100 多个销售、服务、财务方面的预置技能;同时 Microsoft 与 Salesforce 宣布合作推出 Copilotforce,通过 Microsoft Fabric 与 Salesforce Data 360 之间的双向"Zero Copy"集成,把 Salesforce 的客户上下文直接带进 Copilot、Teams 和 Office,附带 38 个预置技能,用于调取客户数据、生成会议跟进和更新 CRM 记录。

个人看法:这篇和今天早些时候的 [Foundry 新模型与持续改进](2026-11-17-microsoft-rolls-out-new-first-party-models-and-updates-to-agentic-ai-continuous-.md) 是同一场 Ignite 的两面:Foundry 是给开发者造 agent 的工厂,Copilot 是把 agent 卖给每个员工的柜台,中间用 WorkIQ/Foundry IQ 这一类"企业知识图谱"把数据接起来。我觉得这次最值得注意的不是 Autopilot 有多聪明,而是三个设计选择。第一,Autopilot 有自己的 Entra 身份,意味着 agent 在企业里被当成一个"数字员工"管理,权限、审计、离职(停用)都走现有的身份体系——这其实是 Microsoft 最难被复制的资产,因为大部分企业的身份和权限本来就在 Entra 里。第二,Agent 365 开始算"每个 agent 的 ROI",这直接回应了 [Ramp 数据显示 AI 支出停滞](2026-11-08-ramp-data-shows-ai-spending-stalling-just-as-anthropic-nears-its-ipo.md) 和 [token 账单冲击](2026-11-17-token-sticker-shock-pushes-enterprises-from-frontier-labs-toward-open-weight-ai-.md) 里的焦虑:企业不是不想用,而是说不清钱花得值不值,谁能先把"完成了多少工作"量化出来,谁就更容易拿到续约预算。第三,和 Salesforce 合作做 Copilotforce,说明 Microsoft 承认 CRM 数据它吃不下,宁愿用"零拷贝"把别人的数据借进来,也要让 Copilot 成为唯一入口;对 Salesforce 来说,这是在 Agentforce 之外多了一个分销渠道,但也有把客户界面让给 Microsoft 的风险。另外,自主 agent 一旦常驻,对可靠性的要求也会变高,上周的 [Microsoft 大规模宕机](2026-11-13-massive-microsoft-outage-disrupts-businesses-government-agencies-worldwide.md) 如果发生在 Autopilot 普及之后,中断的就不只是邮件,而是正在跑的业务流程。

投资角度,先找瓶颈:企业 agent 落地的瓶颈现在有三个,第一是 agent 拿不到干净、有权限控制的企业上下文;第二是 agent 的身份、审计和安全没有现成方案,IT 不敢放权;第三是 ROI 说不清,预算批不下来。这次 Ignite 三个瓶颈都在补,而能补的前提都是"已经握有数据和身份"。受益的层次会是:第一层仍然是算力,常驻 agent 和"Auto 路由 + Cowork 长任务"意味着每个员工背后的推理调用从偶尔几次变成全天候持续消耗,这对 Azure 的 GPU 需求以及 Nvidia、AMD 这类芯片供应商是持续性增量,只是 Auto 会把简单任务路由到便宜模型,单位成本会被压低;第二层是握有企业数据和身份入口的平台,Microsoft 自己最直接,Salesforce 通过 Copilotforce 保住了数据层的位置;第三层是身份安全和可观测性,agent 有了自己的身份之后,Okta、CrowdStrike、Palo Alto Networks 这类做身份治理和行为审计的公司会有新的管理对象,这一层原文没有提到,是我根据产业链延展的判断。相对承压的是单点功能型的 AI 办公工具和低代码平台,Copilot Code 加 Managed Runtime 把"员工自己做小应用"这件事收进了 Microsoft 的围墙里。这篇只挂 AI 板块;Autopilot 是云端常驻 agent,原文没有涉及端侧,不挂 edge AI 板块。

现在 Autopilot 只对 Frontier 计划用户开放,Today 在私有预览,Copilot Code 还要几周才上线,Copilotforce 的定价和上线时间文章也没有说,所以这还是一份愿景清单。值得跟踪的是 Microsoft 下一季财报里 Copilot 席位数和 Agent 365 的收费方式有没有变化,尤其是会不会出现按 agent 或按完成工作量计价的新条目——那才是"Copilot 变成操作系统"真正落地的信号。
