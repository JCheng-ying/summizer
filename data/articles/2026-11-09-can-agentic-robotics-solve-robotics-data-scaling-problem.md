# Can Agentic Robotics Solve Robotics’ Data Scaling Problem?
https://spectrum.ieee.org/agentic-robotics

这篇文章讨论的是机器人行业过去两年最核心的一个押注是否站得住：只要喂进足够多的人类示范数据，机器人就会像 ChatGPT 一样突然"涌现"出通用能力。如果这个假设有问题，那么整个"数据采集公司 + 模仿学习基础模型"的融资逻辑都要重新评估，而文章给出的替代路线，是把机器人编程从"数据问题"变回"写代码问题"。

文章指出，几十年来机器人一直是用 model-based 方法编程的：先建立机器人和环境的物理、数学模型，再由工程师手写极其细致的控制代码，这样的系统快且可靠，但非常依赖人的时间和专业能力，所以后来被"直接喂大量人类示范数据进机器学习系统"的模仿学习取代。UC Berkeley 的 Ken Goldberg（同时是 Ambi Robotics 联合创始人）的判断是，模仿学习范式已经进入平台期：在家用机器人这种对速度和可靠性要求不高的场景还有前景，但工业场景很难达到要求的可靠性——数据带来初始性能，然后出问题，再加数据，又出别的问题，并不清楚继续加数据能否收敛。他也直言，投资人正是押注"数据够了就会像 ChatGPT 一样突然好用"，而大家开始紧张还没看到那个收敛点。

UC Berkeley 和 Nvidia 在 2026 年机器人学习大会（CoRL）上联合提出的 agentic robotics，核心是把任务拆分给多个 coding agent。以"把杂货装进袋子"为例，任务先被分解成子任务：一个 agent 负责感知（识别杂货和袋子），一个负责夹爪的抓取操作，一个负责抓取后的搬运。Nvidia 机器人产品总监 Spencer Huang 的说法是，物体分类、位姿估计、任务与运动规划、轨迹生成这些工具过去二十年早就做好了，问题只是需要人来写代码，而现在 coding agent 可以直接调用这些已有能力生成代码。写好的代码先在仿真里跑，agent 改变初始条件、找失败、迭代修改。文章特别提到一个细节：Goldberg 让 agent 直接调整仿真参数去匹配一段真实世界视频，结果光照、背景这些极其繁琐的设置都被 agent 自动对齐了。为了对抗 AI 生成"slop"，他们用对抗式 agent 结构，一个设计、一个专门挑错。

结果方面，文章指出在 Berkeley 的测试中，agentic robotics 成功率最高达到 99%，与人工手写代码持平，而基线模仿学习方法在同样任务上只有 20%。更重要的是三点：第一，不需要采集数据；第二，用的是现成的 coding agent；第三，生成的代码人能读懂、能修。Huang 给出的近期落地场景是对精度要求极高的工业装配，比如半导体客户要求元件放置误差在 0.3 毫米以内，他直言今天用 GR00T 这种通用平台做不到这种重复性；而在给 Nvidia 生产 GPU 基板的 Wistron，每上一个新产品，重新给一台机器人编程至少要 8 小时，用 agentic robotics 只要一两分钟。

文章也给了反方声音。Alphabet 旗下 Intrinsic 的首席科学官 Torsten Kroeger 认为，目前没有任何物理引擎能准确模拟真实的物理接触，仿真到现实的鸿沟依然没解决；他还提出了对齐问题——当人们开始信任 agent 写的代码而不再逐行审查时，如何确认它始终在做正确的事。

个人看法：这篇文章和之前 [Import AI 479](2026-11-05-import-ai-479-spacewar-low-latency-tasks-versus-llms-genie-4.md) 以及 [Physicl 融资](2026-11-08-physicl-raises-10m-to-make-the-digital-world-real-enough-for-robots.md) 那篇可以放在一起看。目前来看机器人获得能力大概有三条路线：1. 纯数据路线，大规模采集人类示范做模仿学习（GR00T、各类数据采集公司）；2. 仿真路线，在虚拟世界里大量生成训练数据（Isaac Sim、Physicl 这类）；3. 这篇的 agentic 路线，让 LLM 写可解释的控制代码，本质是把语言模型在代码上的规模优势"借"给机器人。我觉得第三条路线最有意思的地方在于 Huang 那句话：agent 生成的大量高质量机器人代码本身又可以成为下一代模型的训练数据，所以它不是和数据路线对立，而是给数据路线提供了一条更便宜的供给。

从投资角度先找瓶颈：工业机器人当下卡住的不是硬件，而是"可靠性 + 换线成本"，Wistron 8 小时 vs 2 分钟的对比就是这个瓶颈最直观的量化。那么解决这个瓶颈的层次是：第一层仍然是算力，coding agent 和仿真迭代都要消耗大量 GPU，Nvidia 同时卖 Isaac Lab、Newton 物理引擎和 GPU，是这条路线上最确定的受益者，利好 AI 板块；第二层是工业机器人本体和集成商，比如 Fanuc、ABB、Yaskawa 这类传统机械臂厂商，以及原文提到的 Siemens、Bosch 这些工业客户，如果换线成本下降两个数量级，中小批量、多品种的产线自动化经济性会明显改善，利好机器人板块；第三层是仿真和物理引擎软件，因为整套方法的上限取决于仿真保真度，这也是 Kroeger 指出的最大短板。反过来，对"只卖人类示范数据"的商业模式来说，这篇文章是一个利空信号。

不过现在还早，99% 的成功率是在相对受约束的工业任务上取得的，Goldberg 自己也说"不想说已经有了解决方案"。值得跟踪的是 Isaac Lab-Arena 上的 agentic robotics 基准公开后，有没有工业客户（尤其是半导体和电子代工）公布实际产线部署和换线时间数据。
